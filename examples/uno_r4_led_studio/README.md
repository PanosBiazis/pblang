# UNO R4 LED Studio

An offline **preview and frame editor** for the Arduino UNO R4 WiFi's 12×8 red
LED matrix, written in PBLang. It never discovers, connects to, flashes or writes
to a board. Existing AVR UNO/ESP32 bridges are intentionally not reused as a
hardware adapter for the different UNO R4 board.

```sh
pblang run examples/uno_r4_led_studio/main.sapp --allow-all -- --gui
pblang run examples/uno_r4_led_studio/main.sapp --allow-all -- --web
pblang run examples/uno_r4_led_studio/main.sapp --allow-all -- --export
```

The Web command prints a loopback URL (`http://127.0.0.1:8768/`) and runs in the
foreground; stop it with Ctrl+C. The CLI export prints a validated initial project
to stdout. No background service or board connection is created.

## Edit and preview

Web **Draw / Text / Animation / Dynamic** choices show the relevant tools without changing
any pixels, frames, selection or unsubmitted text. The chosen workspace is kept
on the next valid action. The matrix, selected frame and preview/navigation
controls remain together. The active workspace actions precede the matrix in
DOM and keyboard order; at widths of 900px and above they sit beside it. Narrow
screens stack the tools before the matrix. **Save / import JSON** is an expandable advanced section.
These controls remain functional without JavaScript.


- Click an LED to toggle it, or focus a native button with Tab and press Enter.
  Web pixels have coordinate/state accessibility labels.
- Choose **Heart**, **Border**, **Checker**, **Clear**, or **Invert**.
- **Duplicate** appends an independent copy of the selected frame at the end; **Delete** keeps at least one frame.
  **Previous/Next** select timeline frames without reordering them.
- Enter a duration from **50 to 5000 ms** and apply **Set ms / Set duration**
  to the selected frame, or **All ms / Set all frame durations** to all frames.
  Changing all durations retains the frame count, pixels and selection; exceeding
  the 60-second timeline budget is rejected without partially changing frames.
- For a static label, enter **1–2 supported glyphs** and choose **Static text**.
  Complete centered 5×7 glyphs fit the 12×8 matrix without cropping. Only the
  selected frame's pixels change; its duration and all other frames remain.
  Longer static input is rejected rather than silently scrolled or truncated.
- Enter **1–8 supported characters** and choose **Scroll text / Create scrolling text**.
  This explicitly replaces the current timeline with editable scrolling frames at
  100 ms each. To change its speed, select Animation and apply a duration to all
  frames. Animation from hand-drawn frames does not require text. No workspace
  switch automatically creates scrolling text or resets existing work.
- Native **Play** / Web **Play preview** starts at frame 1 with the chosen
  **1–8 repetitions**, at most **60 seconds / 128 displayed frames** in total.
  Repetitions are preview settings; they do not duplicate or alter exported frames. **Stop** retains the current frame. Editing stops playback.
  Web uses a finite SVG animation generated by PBLang, with a Stop button next to
  the preview. It adds no JavaScript, polling, refresh loop or recurring timer.
  Browser rendering time starts when the response loads; the server reconciles
  its clock on the next action/page request. This is a visual preview, not a
  hardware timing guarantee. Each pass is labelled; the final frame and completion label remain visible.
  The entire editor is hidden while playing, including its static position,
  duration and status. **Stop playback** restores editing at the current server
  frame; Previous/Next then allow manual inspection. Submissions scroll back to
  the matrix, so playback started from controls below the fold remains visible. With the browser's
  reduced-motion preference, the preview stays on one static frame and explains
  this choice; Stop selects the elapsed server frame, which can differ from
  the reduced-motion static image. Opening/importing does not start
  playback. Already open tabs are independent displays; use one active tab.
- Blank text-entry/exit frames show an unlit matrix and a **blank** label. Identical
  frames retain their own timing and frame numbers even when the pixels do not change.
- In Web text/duration inputs, **Enter does not submit**. Choose the named action
  button (or focus it with Tab and press Enter). This prevents implicit form
  submission from accidentally toggling the first pixel.
- Invalid actions preserve document, selection, clocks and playback; an error
  message may change. Valid native/Web edits with a clock resolve the elapsed
  frame atomically before applying their change. Programmatic `Model.apply`
  calls without a clock retain the already selected frame.
- Native **Frames** creates a new timestamped file beneath
  `build/uno-r4-led-studio/`, using the existing exclusive-write helper. Existing
  files are never replaced. A failed export is explicitly reported and may leave
  an incomplete new file; the application does not claim success on failure.
- Web **Download validated JSON** downloads the current project and its Arduino
  frame words without changing the model or invalidating the current form.

The editor starts with a heart. State is memory-only until explicitly exported.
Closing/restarting discards unexported work. Reopen a saved export using **Import**:
- Native: enter its local path and click Import. The existing secure file reader
  rejects symlinks/unsafe paths and reads at most 128 KiB; no fallback reader.
- Web: open your exported JSON in a text editor, paste its contents into **Paste
  exported JSON**, then click **Import JSON**. There is no file upload picker.

Successful import replaces the timeline, selects frame 1, stops playback and clears
text input and resets preview repetitions to 1. Invalid input keeps the document, selection and playback state; only
an error message changes. Invalid text/duration drafts remain available for correction. The pasted content is not echoed, logged or retained
by the server after the request. It may remain in browser history/form recovery;
this example does not control browser retention. A different button discards the
pasted payload and performs that button's action.

The exact legacy `pblang.uno-r4-led-export.v1` and project
`pblang.uno-r4-led-project.v2` envelopes are accepted, including their exact
mapping and matching authored Arduino words/durations. Project v2 additionally
validates its generator settings; unknown source types are rejected.
Raw canonical documents, additional fields, duplicate keys (including escaped
aliases), excessive nesting, non-binary pixels, malformed JSON and inconsistent
words are rejected. The shared importer accepts at most 131072 UTF-8 bytes,
5 nesting levels, 14000 parser items and 16384 lines. Existing limits of 64 frames
and 60 seconds remain. See the data contract for API examples.

## Dynamic: local timed counter

This source derives its current numeric value from elapsed local runtime time.
It is **not a sensor, serial connection, external data feed or saved animation
sequence**. No counter frame list is created. The authored frames, selection and
frame durations remain independent.

- Choose **Dynamic** on Web, or the **From / To / Every** controls in native.
- From/To are **0–99**. Counting goes up or down automatically, one unit per
  interval. The interval is **1–10 whole seconds**. A run allows at most
  **30 values and 60 seconds**, including the final value's interval.
- **Save counter settings / Save** stores the settings without motion.
  **Start counter / Start** validates the currently entered settings and
  starts from From. Restart begins a new run; opening/importing never starts it.
- **Stop counter / Stop** samples the current elapsed value, freezes that value
  for possible capture, and returns to the unchanged authored frame editor.
  The deadline also stops automatically. A backward clock stops the source.
- **Capture last value → selected frame / Capture** is the explicit operation
  that copies generated pixels into a frame. It preserves that frame's duration
  and all other frames. **Remove counter settings / Remove** clears the source
  without deleting any authored frame.
- Sequence **Play preview / Play** and the counter are independent choices.
  Switching the active preview stops the previous source, retaining the project.

Native samples the generator through the existing update loop. Web renders the
current server-generated sample and uses a same-origin timed page refresh only
while the counter runs. This is an explicit bounded local-clock display, not a
claim that repeated requests discover hardware or obtain a live sensor feed.
The Stop form token remains valid across counter-only refreshes. Stop/completion
removes the refresh instruction. Ordinary editing and sequence playback gain no
refresh loop. Use one active browser tab; existing request budgets still apply.
Slow/background clients can skip intermediate values; elapsed time determines
the current value, without a backlog of frames or a precision-timing guarantee.

### What is saved

**Project JSON** (native Project button / Web project download) contains the exact
`pblang.uno-r4-led-project.v2` envelope: the authored document, matching Arduino
words and optional counter settings. It excludes running state, last sampled
value and clock timestamps. Reopening restores a stopped source at its configured
start, retains the authored document and selects frame1.

**Frames JSON** remains the exact legacy `pblang.uno-r4-led-export.v1` envelope.
It exports only the authored frames and their matching Arduino words; counter
settings are intentionally absent. Older Studio versions can still consume this
export. Importing a legacy file clears absent generator settings. New Studio
accepts both formats through the same bounded strict import path. Invalid
settings/duplicate keys/inconsistent Arduino words preserve the existing project.

Programmatic use uses the same controller and pure counter library:

```sapp
let M=import("./model.sapp");
let state=M.create();
let settings=map{kind:"counter",start:7,end:9,interval_ms:1000};
M.apply(state,"counter_start",settings,10000);
M.tick(state,11100); // value 8; authored frames unchanged
M.apply(state,"stop",nil,11200);
let project=M.export_project(state); // settings retained, timer not persisted
M.apply(state,"counter_capture"); // explicit authored-frame change
```

## Glyph coverage

Reuses `stdlib:bitmap_font.sapp`'s 5×7 glyphs: Latin A–Z/a–z, digits, space,
its punctuation/math symbols, and the explicit Greek subset
**π Π τ φ Φ α β γ δ ε λ μ σ ω Δ Ω**. Examples: `PB`, `12`, `πΩ`.
Some existing symbol/emoji glyphs also work (`←↑→↓`, `❤`, `😀`, `🙂`, `🚀`).
This is not full Greek, Unicode shaping, accents or an emoji font. Unknown glyphs
are rejected before replacing the timeline; they are not silently substituted.
Different lowercase glyphs remain lowercase. No font downloads occur.

## Reuse and boundaries

`text.sapp` renders static glyphs using the existing bitmap font. For programmatic
updates, `Model.apply(state, "static_text", "PB")` updates the selected frame and
`Model.apply(state, "timing_all", 200)` changes the sequence speed. `Model.apply(state, "play", 3, num_floor(now_ms()))` previews three bounded passes.
Calls accept an optional clock for atomic elapsed-frame editing during playback. Callers may
supply changing content explicitly; this example does not poll sensors, run an
external live-data source, repeat forever or claim physical-board transport. The
separate local counter is described above.

`exchange.sapp` owns strict export-envelope import; `playback.sapp` generates the
bounded SVG preview; `web_import.sapp` separates the bounded paste payload before
the existing form handler checks Host/origin/CSRF/revision. The Web transport is
capped at 401408 bytes to allow percent-encoding of a 128 KiB export plus form
fields; decoded input is still capped at 128 KiB. The bounded listener allows
5 seconds to receive a request and polls acceptance at 1 ms so large paste
bodies are not delayed by a 25 ms pause per 4096-byte transport chunk.

`stdlib:uno_r4_led_matrix.sapp` owns pixels, packing, validation, timing and glyph
conversion. `model.sapp` owns editor actions; `view.sapp` uses existing GUI/graphics;
`web.sapp` uses existing UI documents, guarded loopback forms and HTML escaping.
There is no handwritten JavaScript runtime and no new Rust. Web forms retain
same-origin, Host, CSRF, stale-form and script-free CSP checks. Each form rebuild rotates
the token; counter-only refreshes retain the Stop token until completion. Stale forms are rejected and offer a **Return to editor** GET
link instead of replaying the previous POST. Invalid forms use the same recovery. An overall 120-request/minute budget
survives redraws when the existing crawler policy is on; page, style and download
requests count. A budget rejection retains the session, asks for a 60-second wait
and offers the same recovery link. It does not disable the limit or retry actions. Policy options are
independently configurable through `Web.create(port, options)`; opt-outs do not
disable origin/CSRF checks. This is a local preview, not multi-user authentication.

Native execution has an X11 acceptance fixture; supported platform adapters are
not equivalent to tested Windows/macOS/mobile execution. Web uses a loopback
PBLang server, not a standalone exported app. Android/iOS adapters and physical
hardware execution are not provided by this example. The display has only binary
red pixels: no RGB, grayscale, physical 3D display, image decoding, arbitrary nD
projection or hardware driver is claimed.
