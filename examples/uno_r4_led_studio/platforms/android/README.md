# Android companion (debug APK)

This installable application is generated by PBLang directly as JVM bytecode.
No Java/Kotlin source or new JavaScript application is generated. Android SDK
format/signing tools remain build dependencies. It renders the complete existing
PBLang Web editor; the application logic still runs on the paired Linux host.
It is **not a standalone/offline Android runtime or direct USB Arduino driver**.

## Build and open

From the complete PBLang source checkout with a compatible 0.6 runtime:

```sh
pblang run examples/uno_r4_led_studio/platforms/android/build.sapp --allow-all
pblang run examples/uno_r4_led_studio/platforms/android/host.sapp --allow-all
# In another terminal, with an already authorized Android USB device:
pblang run examples/uno_r4_led_studio/platforms/android/install.sapp --allow-all
```

`host.sapp` binds only `127.0.0.1:18774`; do not start a second server if Studio is
already using that port. The server stays in the foreground until Ctrl+C.
The installer selects one authorized device using `stdlib:android_adb.sapp`.
Ambiguous devices require explicit `PBLANG_ANDROID_SERIAL`; it never chooses
silently or enables USB trust. ADB operations have time limits.

The APK appears under `build/uno-r4-led-studio/android/`, with SHA256 and manifest
sidecars. It has the distinct identity `org.pblang.unor4ledstudio`, Android API21+
and target34. This is a **debug-signed**, debuggable development build, not a Play
Store release or production publisher signature. The local signing key is not
part of the source package. Building uses the existing local SDK toolchain.

The installer creates an explicit USB reverse tunnel for port18774 and opens the
Activity. Keep the Linux host/server and USB connection active. When finished:

```sh
adb -d reverse --remove tcp:18774
```

Use a device selector if more than one device is connected. Removing the tunnel
disconnects every client on that device using this port. Closing the application
does not automatically stop the host or remove the tunnel.

## Behavior and boundaries

- Draw/text/animation/counter controls use the same guarded forms and shared model.
- Android and desktop browser tabs share one host project. Prefer one editing
  client at a time; old forms can be rejected instead of replaying a stale action.
- The native desktop editor has separate memory. Exchange saved project JSON when
  transferring work; the apps do not silently synchronize independent projects.
- JavaScript, WebView file access and content-provider access are disabled.
  Backup is disabled. The only manifest permission is INTERNET; no camera,
  microphone, storage, Bluetooth or USB-device permission is requested.
- The generated page uses only local resources. HTTP is restricted by the app's
  fixed loopback start URL and host-only protocol; the legacy WebView generator
  permits cleartext traffic at manifest level, so this is not a universal WebView
  navigation/network sandbox. No external origins or scripts are in Studio pages.
- JSON paste import works. APK file-picker/download integration is not implemented;
  save/download from the paired host browser. Unexported host state is memory-only.
- Preview Play does not command the physical matrix. Use the separately documented
  Linux device route for explicit physical-board operations.
- Disconnecting USB or stopping the server makes the companion unavailable. To
  retry, reopen the app after restoring the connection; no hidden reconnect loop.

## Explicit physical controls through the Linux host

After uploading a verified PBLang UNO project using `../../DEVICE.md`, replace
`host.sapp` with this explicitly configured foreground host:

```sh
pblang run examples/uno_r4_led_studio/platforms/android/device_host.sapp --allow-all -- /absolute/project.json /dev/ttyACM0 4 --confirm-uno-r4-wifi
```

Use the confirmed port and repetition count of the installed firmware. The host
loads that saved project, then offers **Check Arduino / Play on Arduino / Stop
Arduino** separately from preview controls. Opening an app/page never accesses
the port. Each device button uses the existing origin/CSRF/revision/rate checks,
then the bounded serial handshake. Edited projects are rejected before physical
Play until exported, compiled and uploaded separately; this does not automatically
flash the board. Stop and Status retain the installed project binding after edits.
Device Stop remains accessible even while screen preview hides the editor.
A device acknowledgement is not proof of visible LED output. The status is a
snapshot; there is no automatic polling or replay after failure.
