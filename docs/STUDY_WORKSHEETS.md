# Study material to Writer worksheets

The roadmap's lesson/template-pack direction already connects Writer notes, slides and study cards. PBQuiz adds explicit question sheets and separate supplied-answer keys. PBLesson exposes the same conversion in native/CLI. No additional scan or private-data intake was performed; existing documentation supplied the workflow idea.

text_document.split_text(text,max_bytes=1024) reuses strings.chars and produces exact code-point chunks, each within the byte limit. Input is at most 32768 UTF-8 bytes and output at most 64 chunks; limits must be integer 1–1024, too-large single code points reject. Empty text returns one empty chunk. NUL is rejected as in Writer. It preserves code points, not grapheme clusters. The helper joins per-chunk arrays once, avoiding repeated indexed Unicode slicing; no measured speedup is claimed.

study_worksheet.create(deck,kind,first,count) validates the complete canonical study deck and accepts questions/answers plus a saved-order 1-based range of 1–16 cards. Question headings retain source position/ID, followed by unchanged prompts and a response line. Keys contain corresponding exact answers, chunked to fit Writer blocks. Source title is preserved. No review dates or progress change. Final Writer validation catches block/total-byte overflow including added headings; select fewer cards. No partial document or truncation.

study_worksheet_files opens existing bounded .pbdeck/.pblesson via canonical validators and secure_file, then saves one new Writer copy through text_document_files. No new persisted format, registry dependency, network, telemetry or hidden persistence. Files retain user content and remain until user deletion. Questions omit answer fields, not necessarily answers already present in prompt/title; no exam-security guarantee. Failed writes may leave partial new files.

PBQuiz native preparation preserves last good state on failures and blocks export after changed range fields. PBLesson exports all lesson cards natively or an explicit range via CLI. Existing revision/allocation workflows are retained. Web/Android worksheet pages reuse document_excerpt_view, four blocks/page, with Show/Hide. Only selected-page document content is embedded; Hide is not access control. Portable editing, PDF printing, installed platforms, grading and randomization are separate work.
