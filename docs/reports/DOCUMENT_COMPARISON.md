# Structured document comparison — 2026-09-27

PBCompare adds a local two-file inspector; PBOffice Writer adds checkpoint comparison. This builds on the document utilities direction in `MIGRATION_INVENTORY_2026-08-21.md` and the catalog's documented comparison/document categories. The new combination compares document revisions without requiring Git, then exposes the same semantics in Writer. No new whole-disk content scan, private sample ingestion, third-party implementation reuse or model training was performed.

## Common modules

- `sequence_diff.compare(left,right)` accepts up to 128 strings per side, each at most 2048 UTF-8 bytes and each side at most 65536 bytes. Empty sequences and strings are valid. It validates before alignment, anchors common prefix/suffix, then uses an integer LCS matrix on the remainder: O(n*m) worst-case time and space, at most 16641 matrix cells. Returned operations are detached `{kind,left,right}` index records, with nil for the absent side; counts describe insertion/deletion minimum distance. Whitespace/case are exact. Anchoring fixes boundary matches; interior ties prefer deletion. It does not promise globally identical tie choices to an untrimmed algorithm on repeated data.
- `document_compare.compare(left,right)` validates Writer models and uses unambiguous `kind + NUL + text` keys (Writer disallows NUL). It returns counts, exact titles, an identical flag and detached blocks. A title change is a separate first entry. Replacement is delete+insert; moves are not detected. `encode(left,right)` regenerates the report rather than accepting unvalidated report data; its format is `pblang.document-comparison.v1`, with a 524288-byte ceiling.
- `document_compare_view.create(left,right,index=0,group=0)` creates read-only snapshots for one entry and a group of at most eight selectable six-line text fragments. Native inspectors navigate every entry/fragment. Static export requires explicit entry/group selection. This avoids truncating long blocks or generating thousands of UI actions. Display uses the existing bounded `text_pages` cluster model, not full Unicode grapheme/line-break conformance; JSON remains exact.
- `text_document_files` contains the canonical existing Writer file operations. `writer_store` is a compatibility facade. Parallel document-workflow development also uses this module; the validated implementation is retained rather than introducing a second parser.

No caller inputs mutate. A failed pair load retains the prior comparison. File behavior preserves exclusive new copies, supported suffix/byte budgets and existing Writer errors. No source document is rewritten by comparison. JSON exports include document text and are explicit, local outputs; failed copies may be incomplete, without atomicity or crash-durability claims.

## Tests and performance

The sequence suite exhausts all 225 pairs of binary sequences of length 0..3 against an independent recursive LCS oracle and reconstructs both sides from every operation stream. It also covers full 128-item equal/disjoint inputs, Unicode, empty values, malformed types and per-item/aggregate limits. Document/view tests cover insertion without spurious shifts, kind/whitespace/title changes, detached results, strict Writer roundtrips, full Unicode text, final fragment groups and malformed indices. Product tests exercise real widget routes, pending-draft guards, unchanged history/baseline, failed-load retention, text navigation and actual new-file operations. Existing Writer/model/page suites remain regression gates.

`bench/sequence_diff.sapp` compares the complete trimmed result with a benchmark-only full-matrix reference with identical validation/reconstruction. Workloads contain 64 identical blocks, one changed middle block, and fully disjoint blocks. Each runs two warmups and seven wall-clock samples; median and nearest-rank p95 (maximum of seven) are reported. Both measured outputs are asserted identical for these workloads. Common boundaries avoid most matrix work; fully disjoint inputs retain quadratic cost. Measurements do not represent entire application speed, isolated CPU cost, all duplicate tie cases or physical-platform parity.

Linux native windows are exercised in an isolated X11 display using timed callbacks. Web fragment selection is checked separately in a browser. Android Activity class/manifest generation is not installation/device execution. Packaged Windows/macOS/mobile releases, two-file browser opening, merges and word-level changes remain future work.
