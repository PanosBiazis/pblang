# Typed scalar collection keys

The PBLang-only `collection_keys.sapp` implementation is shared by
`functional.unique`, `array.unique`, `array.distinct_by` and the new
`functional.unique_by` and `functional.group_by_entries` APIs.

```sapp
let F = import("stdlib:functional.sapp");
let values = F.unique([1,"1",1,true,"true"]);
// [1,"1",true,"true"]
let rows = [map{id:1,label:"first"},map{id:"1",label:"text"},map{id:1,label:"later"}];
let firsts = F.unique_by(rows,fn(row) { return row.id; });
// First two original objects, in encounter order.
let groups = F.group_by_entries(rows,fn(row) { return row.id; });
// [{key:1,items:[rows[0],rows[2]]},{key:"1",items:[rows[1]]}]
```

## Identity and compatibility

Keys are strings, booleans, nil or finite ordinary `number` (f64) values.
Types remain distinct. Signed zeros share a bucket under numeric equality;
the first representative, including its original zero sign, is retained.
Buckets include a type tag and comparisons confirm scalar equality. Finite
rendering collisions were not reproduced on the checked round-trip formatter;
the equality check avoids relying on display text as proof of identity.

The prior functional helper merged number/string and boolean/string values by
`str(x)`. Array distinct-by used type plus rendering without scalar validation.
Both now use exact supported scalar comparisons. Array unique no longer calls
the legacy raw builtin, giving the two stdlib unique APIs the same contract.

This intentionally narrows formerly accepted inputs: structured keys (including
arrays/maps/functions/modules), bigint/rational/decimal, nonfinite values and
oversized inputs now throw. For objects use an explicit scalar projection.
Do not stringify arbitrary objects as a workaround: that reintroduces lossy or
recursive identity. Cross-representation exact-number equality is not implemented.
This change must be considered during the broader pre-1.0 compatibility review.

Legacy `functional.group_by` and `frequencies`, plus map/index helpers, still
return string-keyed maps and retain their existing conversion/collision behavior.
The additive `group_by_entries` represents typed keys without silently changing
those return shapes. `array_unique` itself is unchanged and should be treated as
a legacy unsafe boundary for arbitrary composite inputs: retained-host recursive
equality lacks a visited/depth bound, and C99 composite equality uses identity.
The wrapper fix does not close direct builtin access.

## Bounded operation

Each call accepts at most 4096 input items; input type/size is checked before
callbacks. Text keys have at most 4096 language characters. Aggregate encoded
bucket text, including type prefixes and duplicate occurrences, has a 65536
character limit. Ordinary numeric/boolean/nil encodings also consume that budget.
At most 65536 candidate equality comparisons are performed. Failures throw rather
than return a misleading partial result. Diagnostics generated by the helper are
constant text and do not include input values.

Character counts are not byte counts: UTF-8 can require up to four bytes per
character. These limits bound helper-owned key material and membership counts,
not aggregate VM heap, source input size, map overhead, callback allocations,
callback time or payload sizes. Callbacks remain trusted executable code.
Colliding buckets can require quadratic comparisons until the comparison budget
rejects; no unconditional O(n) or throughput improvement is claimed. The helper
also builds intermediate groups for deduplication, an explicit memory tradeoff.

Callbacks run once per visited original item, in order. A required callback error
propagates immediately; no later item is visited. Length changes are rejected
after callbacks. Same-length replacement/reordering and mutate-then-restore are
not detected: callbacks must not structurally mutate the input array. There is
no snapshot/ABA guarantee or rollback of callback side effects. Returned payloads
remain original borrowed references, not deep copies. Empty input invokes nothing.

## Verification and remaining limits

Focused tests cover mixed types, nearby f64 values, both zero orders, nil, Unicode
and embedded NUL on the retained host, projection order/counts, borrowed objects,
typed group/member order, legacy string-map compatibility, required callback
errors, malformed input, structured/cyclic-key rejection without traversal,
exact-number/nonfinite rejection, 4096/4097 item/key limits, aggregate limits
and callback length mutation. Cyclic values are tested only as rejected projection
keys; the raw recursive builtin is not executed on cycles.

The actual functional/array modules are imported and executed through the bounded
PBLang frontend/VM with 30000 steps, 32 frames, eight modules and 32-KiB source
limits. C99/native/device equivalence is not established. In particular, C99's
NUL-terminated string/map primitives cannot preserve embedded-NUL key semantics;
this requires separate runtime work. Comparison-budget exhaustion is statically
guarded but not fault-injected in these tests. Mutable VM descriptors, hard heap/
preemption, raw FFI/builtin closure and hostile-code isolation remain open.
