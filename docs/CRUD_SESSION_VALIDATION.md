# CRUD issued-session validation

## Change and scope

The existing private session map already contains only 64-character lowercase hex
identifiers generated by `_token()`. Cookie parsing now uses exact membership in
that map to avoid constructing and validating a 64-element character array again
for every active token. Unknown tokens still receive the complete syntax check.
All cookie pairs are still parsed, including those following a known token:
duplicates, malformed values, oversized headers and duplicate header names retain
their previous rejection behavior.

Membership proves only that a token was issued, not that its session is signed in.
Authentication, CSRF, expiry, logout, catalog reload and close still use the same
state and gates. No additional cache retains old tokens after revocation. The map
is private to the guard; caller-supplied request fields never insert entries into
it. This is an optimization for serialized use of the existing CRUD guard, not a
new concurrency or hostile-code isolation guarantee.

The change applies to both inline and saved accounts, and therefore to the native
CRUD example and standalone product when they use this updated library. It adds
no polyglot source or native dependency. Bcrypt still uses libxcrypt through FFI.
The installed PB-MCP was not updated by this slice.

An earlier experiment refactoring the extra saved-account guard invocation was
**discarded** after its median CPU increased from 0.74 to 0.76 seconds in a small
comparison. None of that refactor or its new cleanup helpers was retained.

## Verification

Nine targeted suites passed: account-cookie validation, existing account behavior,
saved-account lifecycle, persistent accounts, catalog codec, persistent live reads,
persistence, preview and records. The new cookie regression also passed against
the parent implementation, checking behavioral parity rather than a new rejection
policy. Cases include an issued anonymous token that must never grant access,
duplicate cookies after a known token, unknown canonical tokens, malformed Unicode
and newline tokens, extra separators, oversized headers and closed guards. Existing
suites exercise real bcrypt login, logout, expiry, removal and failed/recovered
catalog reload.

A real loopback HTTP login passed using the example's saved-account mode. Generated
credentials stayed in memory in the test runner; the listener was stopped and
reaped. This did not retest or fix immediate same-port rebinding. Build/lint,
entry-only static checks, the standalone native product test and portable-lock
publication were run in isolated fixtures. Entry-only static scans are not a full
security audit or a runtime protection guarantee.

## Reproducible measurements

Parent: `e0894fefd01fbe7ed5c0970282989e01fec13251`. Same retained executable,
synthetic account/hash, requests and isolated dependency closure; one warmup and
seven measured samples per case with alternating before/after order. Each run
includes startup, one real bcrypt login and the stated count of in-process GET
requests. `/usr/bin/time` records whole-process CPU, wall time and peak RSS. These
are handler measurements, not HTTP throughput or end-to-end browser performance.

| Requests / catalog | Median CPU before -> after (s) | Sample p95 CPU (s) | Median peak RSS before -> after (KiB) |
| --- | --- | --- | --- |
| 1,000 / saved | 0.75 -> 0.73 | 0.88 -> 0.77 | 31892 -> 31672 |
| 1,000 / inline | 0.70 -> 0.68 | 0.74 -> 0.75 | 31396 -> 31392 |
| 10,000 / saved | 1.09 -> 0.91 | 1.12 -> 0.99 | 31932 -> 32012 |
| 10,000 / inline | 1.08 -> 0.86 | 1.20 -> 0.93 | 31456 -> 31552 |
| 10,000 unknown canonical tokens / saved | 1.14 -> 1.11 | 1.27 -> 1.16 | 32044 -> 32564 |

Saved accounts used about 2.7% less CPU at 1,000 requests and 16.5% less at 10,000.
Inline accounts also improved in these median measurements. The saved-versus-inline
cost remains: 0.73 versus 0.68 seconds at 1,000 and 0.91 versus 0.86 at 10,000.
The historical 4.2%/1.2% overhead was not proven eliminated. RSS increased by about
0.3% for saved accounts at 10,000 and 1.6% for unknown tokens; no general RAM saving
is established. The small inline sample p95 worsened. With seven samples the
nearest-rank p95 is the maximum sample, not a production tail-latency bound.

`bench/crud_account_sessions.sapp` preserves the workload in source. Set
`PBLANG_ACCOUNT_BENCH_REQUESTS` to 1000 or 10000. Leave
`PBLANG_ACCOUNT_BENCH_CATALOG` empty for inline accounts, or set it to a private
synthetic catalog provisioned with the exact test hash in that benchmark for saved
accounts. Never use a real account database for this known test credential.
The unknown-token comparison substitutes a 64-zero token and checks redirect 303,
with everything else unchanged. Raw samples and the local orchestration scripts
are retained outside the repository.

## Remaining work

Immediate restart still requires a supported socket-option boundary: this retained
host's typed FFI accepts at most four arguments, while `setsockopt` requires five.
No raw syscall, generated machine-code bypass, new C/Rust shim or socket behavior
change was added here. Full application conversion, spatial/multidimensional
interfaces, general runtime/FFI/GC work, pure-PBLang bcrypt, public account-management
features and Windows/macOS verification remain open. No EnterpriseOrg server was used.

Graphify update exceeded a 20-second bound. Its process group was terminated and
reaped; the graph refresh did not complete.
