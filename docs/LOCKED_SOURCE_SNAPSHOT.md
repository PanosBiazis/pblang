# Locked source snapshots

`stdlib:locked_source_snapshot.sapp` loads a bounded Linux project and its local
path dependencies into an in-memory module map. `source_inliner` and
`immutable_broker_bundle` consume that map. A valid lock now means the actual
`pblang-package-tree-v2` byte contract used by the package manager, rather than
the legacy file-only digest previously accepted under the v2 label.

The canonical stream begins with `pblang-package-tree-v2` followed by a zero
byte. Every file **and directory** is sorted by its UTF-8 relative path and
contributes: one byte (`f` or `d`), an eight-byte big-endian path-byte length,
path bytes, an eight-byte big-endian content length, and file bytes. Directory
content is empty. Hidden entries, `target`, empty directories and binary assets
all contribute to dependency verification. The dependency root itself does not.
Project-only module discovery retains its existing hidden/target exclusions.

Before collecting modules, the loader now validates lock metadata with the
existing strict TOML subset parser. Duplicate fields/tables, malformed lines,
scalar/table conflicts and unsupported values are rejected rather than silently
overwritten. Bare-compatible identifiers may be single- or double-quoted,
including table components; quoting does not create a distinct key for duplicate
checks. Escaped identifiers, dots or spaces inside a quoted identifier remain
outside this strict subset. Metadata must decode as exact UTF-8 bytes. The lock's dependency
names must match the local names extracted from the manifest, and a local lock
record may not also declare a `source` marker. Empty dependency sets are valid.
This checks lock admission; the manifest path extractor remains a separate,
limited parser and is not a complete validator of arbitrary manifest grammar or
all registry/Git declarations. Those forms are not newly supported here.

Existing callers still use `load(project_root)`. Successful results add
`dependency_digest_backends`, keyed by dependency name:

- `vm-sha256-utf8-canonical`: the entire stream can be represented losslessly as
  UTF-8 text and is within the 16 MiB canonical buffer limit.
- `pure-pblang-incremental`: a complete independent reread uses incremental
  SHA-256 in PBLang. No state from an unsuccessful fast attempt is reused.

Lossless checks include the binary length fields. For example, a 128-byte
ASCII file needs the pure path because its length contains a standalone `0x80`;
a 256-byte ASCII file can use the fast path. Invalid UTF-8 module source is
rejected; binary non-module assets remain supported. The inventory no longer
reads each file merely to discover its size; each pass captures its file bytes
once, and hashes exactly those bytes used for its returned modules. Directory
listings are reused during recursion. This removes redundant I/O, without
claiming a universal speedup over the formerly incorrect digest.

## Bounds and limitations

The loader retains its limits of 4,096 files, 4,096 entries per directory,
64 directory levels, 16 MiB per file and 64 MiB total file content. A new
8,192-entry aggregate inventory bound includes directories. Symlinks and
unreadable/unsupported file entries fail. The loader uses literal-relative
directory listing and file reads, so a top-level file or directory named `root`
is supported. Only the empty directory path addresses the held root; `.` and
`..` are rejected by these APIs. See [relative paths](LINUX_DIRFS_RELATIVE_PATHS.md).
It does not claim support for every package accepted by the native manager.

Local inline path dependencies and portable relative lock paths remain required.
Native locks can be converted using `portable_lock.publish(project_root)`;
normalization preserves the digest. Locks containing the former legacy digest
must be regenerated by the package manager, rather than merely relabeled.

These are immutable returned strings, not an atomic filesystem-wide snapshot:
concurrent namespace changes and forced runtime termination remain outside this
contract. Directory listing currently materializes the host listing before its
entry-count check. File content reads retain the existing bounded no-follow
implementation. No new native library or external service is introduced.
Successful ordinary returns now also require directory-root cleanup to succeed;
this is not a general exception/OOM cleanup guarantee.

## Verification

`tests/tooling/locked_source_snapshot.py` compares native-generated lock digests
with Python SHA-256 and then exercises the real PBLang loader after portable
normalization. It covers length-field boundaries, Unicode paths, binary bytes,
hidden/target entries, literal `root` files/directories (including a real import),
empty directory mutations, stale legacy digests, link and
special-file rejection, and a real broker bundle executed without dependencies.
The semantic snapshot and bundle tests use fixed independently computed digest
answers instead of duplicating the implementation under test.

Production changes are PBLang source. The retained native executable is unchanged.

`tests/tooling/snapshot_lock_admission.py` exercises the snapshot and broker APIs
together using a genuine native-generated portable lock, contradictory duplicate
fields, extra/missing/renamed dependencies, mixed origin records, malformed TOML,
invalid UTF-8 and an empty dependency set. Every case checks source preservation.
