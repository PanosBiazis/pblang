# Words and subtitle reading density

PBWords and PBMedia reuse a new bounded `text_metrics` module, and Writer `text_document.statistics` uses the same counting contract. Inspiration: Unicode/text fundamentals in `MIGRATION_INVENTORY_2026-08-21.md`, existing Writer notes and subtitle workflows; the new vocabulary-to-Sheets bridge is original work. Existing scan documentation was consulted; this change did not scan private document contents or import third-party implementations.

`text_metrics.count(text)` accepts up to 65,536 UTF-8 bytes and returns Unicode scalar characters, nonspace characters and literal whitespace-token count. `tokens(text)` shares exactly the ASCII space/tab/CR/LF boundary rule. There is no case folding, normalization, punctuation stripping, stemming, grapheme counting or linguistic segmentation. The original Writer meaning and return schema remain unchanged; title is excluded from body counts. The implementation splits into scalars once instead of repeatedly indexing a Unicode string.

`word_profile.analyze(doc)` validates a Writer document, limits to 256 distinct tokens of at most 256 bytes, counts once with an index map, records unique zero-based block locations and uses a stable frequency ordering. Equal counts retain first appearance order. `page(doc,index)` selects eight entries by zero-based page; empty body has one page. `to_sheet` preserves exact tokens and shows one-based block/page labels. `word_profile_view.create` shares a selected page across native/Web/Android; all entry details are embedded, not hidden private content. Native PBWords paginates long text independently of result pages.

`subtitle_reading.analyze(doc,limit=20)` returns per-cue counts, duration, nonspace scalar characters/second and strict-above-limit flags plus peak and count. `next_above` wraps; no matches returns nil. Limit is a caller-selected finite 0..1,000,000 value, not a recommended standard. Source text, timestamps, history and saved state are not changed by diagnostics. Markup is literal, combining marks count separately and overlapping cues are not combined into a viewer-level load measure. PBMedia keeps its existing timing diagnostics and statistics schema.

Verification: five library suites (three new and two regressions), three PBMedia native-model suites and two PBWords suites; strict builds/manifests; lint with warnings. Native event-loop and browser evidence are recorded separately from generated Android classes. Linux operation does not prove Windows/macOS/mobile installation. Native workspaces are fixed 1100×1000 (PBWords) and 1100×1100 (PBMedia). Web/Android are readers, not editors.

Benchmark: `pblang run bench/text_metrics.sapp` compares the previous Writer algorithm with the new implementation using identical 32-block Greek text, identical validation and return maps. Two warmups, seven wall-clock samples; equality asserted. Median: 21.119 → 9.760 ms (2.16×); nearest-rank p95: 22.056 → 10.425 ms. This is a local operation-specific result under concurrent host load, not a whole-app/cross-platform guarantee.

New-copy saves retain existing exclusive-write semantics; partial failed copies remain possible. No overwrite/atomic-durability promise. Products expose structured error results. Publication artifacts should omit local data, generated previews/build outputs and machine-specific paths.
