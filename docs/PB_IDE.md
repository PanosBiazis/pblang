# pblang-native IDE — browser-free, for total security

> **Goal.** Make the IDE completely written in pblang — no HTML, CSS, or JS — while matching the web IDE's workflow as closely as possible.

The native IDE is the self-hosted Studio direction of the project: editor, terminal, designer, AI helper, browser, and run/check history are pblang code running on pblang's own runtime. The Code panel runs and checks through `stdlib/compiler/selfhost_frontend.sapp`, and the tested self-host path can bundle imports and emit `.pbck`; the Rust VM remains the native execution kernel and fallback for now. The web IDE remains useful as a bootstrap/reference UI, but the native IDE is the long-term security-first target.

---

## Why — the security argument

The browser IDE (`editors/ide/index.html`) is convenient, but a web IDE brings browser attack surface:

| Web-stack layer | Attack surface it adds |
|---|---|
| HTML parser | malformed-markup / injection bugs |
| DOM + `innerHTML` | XSS and content-injection bugs |
| CSS engine | layout/parser exploits and data exfiltration tricks |
| JS engine | JIT bugs, prototype pollution, dependency surface |
| `fetch`/iframes | SSRF, content-injection, sandbox escapes |

A pblang-native IDE removes those layers. The whole IDE is a native window, a pixel buffer, input events, and pblang code under pblang's capability model. There is no DOM, no JS runtime, and no HTML renderer to exploit.

This reduction in browser attack surface is not a complete hostile-code sandbox.
PBIDE now starts in `untrusted` effect mode: direct Open, Save, Run, and Terminal
actions fail closed before their filesystem or process builtin. The pure
`stdlib/pbide_effect_admission.sapp` contract can prepare a digest-bound,
bounded, expiring request, but it deliberately cannot authorize or execute it.
A future out-of-process broker must independently authenticate the operator,
verify the publisher and runtime/import closure, resolve paths without following
symlinks or reparse points, enforce compare-and-swap, consume a single-use nonce,
apply process containment, and execute the effect.

For local compatibility only, an operator who launches the source directly with
environment capability may set `PBIDE_UNSAFE_LOCAL_EFFECTS=1`. That restores the
legacy direct actions and is explicitly unsafe: the setting is not authentication,
does not provide hard preemption, and must not be used as release evidence. The
canonical `pblang ide` launcher denies environment access, so it remains in the
fail-closed mode. Other ambient PBIDE surfaces and startup reads still require a
complete broker/sandbox migration before the IDE is production-ready.

## Architecture

```text
        ┌─────────────── editors/ide/pbide.sapp ───────────────┐
        │  native window + event loop                           │
        │  code editor | terminal | designer | AI | browser      │
        │  self-hosted run/check + toolchain status               │
        │  history snapshots + restore                           │
        │  fail-closed effect admission (external broker needed) │
        ├───────────────────────────────────────────────────────┤
        │  stdlib/editor_model.sapp   buffer + cursor + edits   │
        │  stdlib/graphics.sapp       AA text + window/present   │
        │  stdlib/text_layout.sapp    pblang shaping / bidi      │
        │  stdlib/bitmap_font.sapp    fallback 5×7 glyphs       │
        │  stdlib/browser.sapp        fetch + reader parser     │
        │  stdlib/browser_render.sapp optional host screenshot  │
        │  stdlib/gui.sapp            designer widget model     │
        │  stdlib/design_engine.sapp  responsive 2D/3D layout   │
        │  stdlib/ui_observer.sapp    structured UI snapshots   │
        │  stdlib/pbai.sapp           local pblang assistant    │
        │  stdlib/graphics.sapp       window / rect / present   │
        └───────────────────────────────────────────────────────┘
```

## Current native panels

- **Code / document / media editor** — editor-style file tabs, syntax highlighting, selection, undo/redo, find, save, run, check, output pane, watcher, file preview, and a visible toolchain block showing the self-hosted pblang frontend plus native VM boundary. PBIDE now profiles TXT/CSV/DOC/DOCX/ODT/RTF/PPT/PPTX/XLS/XLSX/PDF/image/audio/video assets, shows active editor/player mode in the status bar, cycles preview modes, exposes tool palettes plus structured decoder/export/player backend readiness for document/spreadsheet/slides/PDF/image/audio/video workflows, and blocks unsafe direct Save for binary assets with explicit backend requirements.
- **Terminal** — defaults to broker-required and performs no process launch. The legacy `proc_spawn_wait` path is available only when the source is launched with process/environment capability and the explicit `PBIDE_UNSAFE_LOCAL_EFFECTS=1` compatibility opt-in; that path is not sandboxed or production-ready.
- **File-broker transaction substrate** — `stdlib/pbide_file_broker_core.sapp`
  now validates an exact, bounded, open/save-only request contract. It binds raw-byte
  payload, expected-state, runtime, and bundle digests; opaque workspace/state handles;
  a short-lived nonce; and a strict relative path. `stdlib/secure_file.sapp` supplies a
  Linux-only private-root cooperative CAS and durable consume-once nonce receipt. The
  nonce is burned before a target effect, and uncertain publication is non-retryable.
  Receipt admission and missing-CAS now use atomic no-replace directly rather than
  enumerating the directory, so unrelated ledger entries do not create a 4,096-name
  correctness ceiling. Metadata and content verification come from one held descriptor;
  only exact, durable, newly published evidence sets `effect_admitted=true`.
  This is deliberately not wired into PBIDE yet: publisher authenticity, immutable
  runtime handoff, external process evidence, and descriptor resolution remain false,
  so planning grants no file/process/network/FFI authority. The CAS protects cooperating
  same-UID writers that honor its lock; it is not hostile shared-workspace isolation.
- **Design** — native visual designer with label/button/textbox/checkbox/radio/select/slider/panel plus document page/rich-text/image/table/media palette, app target mode (`gui` / `web` / `both` / `doc`), 2D chart, runnable 3D cube/ball widgets, scanner placeholders, N-dimensional item placeholders, custom/web component placeholders, and game-engine-style placeholders for camera, light, material, terrain, particles, physics body, prefab, and OpenGL/Vulkan-style render backend targets. It supports responsive layout cycling, bounded drag/move/edit behavior, snapped placement/drag/keyboard nudging/resizing, selection cycling, duplication, layer ordering, selected-widget property inspection, reusable component-library suggestions, document-output/export planning, and parse-checked `->CODE` generation into the editor.
- **AI** — local pbAI assistant with quick actions: explain, bugs, improve, quality, comment. The assistant exposes structured analysis metadata, prompt-history recall, draft restoration, and raw scan metrics.
- **Browser** — pblang-native safe Live/Reader/Source/Inspect view using `stdlib/browser.sapp` to enforce an HTTP/HTTPS URL policy, block unsafe schemes/private hosts/credential URLs/CRLF input/non-web service ports plus known ad/tracker/malicious URL patterns by default, fetch pages, decode entities, strip scripts/styles, extract page blocks/images/links/forms, create deterministic native layout boxes for Live mode, hit-test Live boxes for link navigation/image selection/form editing, clean noisy reader lines, deduplicate repeated navigation text, list discovered forms, show numbered HTML source, show F12-style details, resolve address-bar search queries through selectable search engines, keep local bookmarks, create policy-checked download plans, navigate back/forward/home, show page stats, and search visible page text. The Browser panel also has editor-style tabs: examples can seed several URLs, `Ctrl+T` opens a new tab, and `Ctrl+PageDown` / `Ctrl+PageUp` switch tabs while preserving per-tab mode, URL, scroll, page, reader, source, inspect, and form state. The Browser header now shows both the security policy and a native-interaction boundary line: links/forms/images are interactive, but full JavaScript/DOM execution is not native yet. `Host` is an explicit opt-in external snapshot fallback through `stdlib/browser_render.sapp`, and `JS/DOM` is an explicit host-render security profile rather than the default pblang-native renderer.
- **Files** — persistent pblang-native project browser backed by `fs_listdir`. It lists folders before files, supports type-to-filter, flat/tree/recent mode with `Tab`, bounded recursive tree browsing, multi-root bookmarks/cycling, editable root labels/groups, breadcrumbs, clipboard status, directory navigation, refresh, mouse selection, opening files into the editor, selected-item previews, inspection summaries, safe copy/cut/paste/delete/rename/new-folder operation planning, and FileZilla-style remote transfer planning without storing credentials.
- **History** — web-IDE-style run/check snapshot list. Every native Run/Check records status, output summary, source snapshot, and storage mode. History supports temporary memory-only mode, permanent JSON-backed saving under `HOME/.pblang/pbide-history.json`, visible stored/unsaved state, click-to-restore, explicit Delete Selected, and Clear All.
- **Management** — native management dashboard for databases, history/storage, project files, browser/security, browser data, document/media backend readiness, AI/model state, backup/export planning, Graphics/GPU runtime status, AAP one-command status, AAP portfolio readiness/action planning, and bounded project text audit status. Browser data summarizes bookmarks, recent policy-checked download plans, security route, and selected search engine. Database management now exposes tested profiles/status/action plans, while real database execution remains gated.
- **Settings** — searchable native preferences tab for theme, visual style, responsive density, build mode, watcher, browser/security/search, file roots, history storage, font/text renderer, and Graphics/GPU/CPU render route. Click or press Enter on a setting to apply it or jump to the owning panel.
- **Project improvement board** — Management can consume the pblang-native
  `project_survey` contract through `ide_features.project_improvement_board(...)`.
  It classifies safe path metadata from AAP/project roots, skips secret/cache/build
  locations, and shows focused PBIDE/pblang/pbAI/pbOS/MCP improvement ideas without
  reading private file contents or slowing the renderer.
- **AAP portfolio readiness board** — Management now consumes
  `ide_features.project_portfolio_board(...)`, backed by
  `project_survey.portfolio_readiness(...)`, to show the same safe readiness
  contract across pblang, pbAI, pbOS, PBIDE, pb-mcp-server, and PBRemote. It reports
  present/missing focus categories, readiness scores, device routes
  (CPU/GPU-present/parallel/polyglot/tool gates), top priorities, and safety
  gates. Opening the row prints a compact line report. It still uses metadata
  only: no private file contents are read, no training data is ingested, and no
  tool command is executed.
- **pblang ecosystem product health** — Management also exposes
  `ide_features.project_product_health_board(...)`. It converts the same safe
  metadata survey into versioned `pblang.product_health.report.v1` rows for
  pblang, pbAI, pbOS, PBIDE, pb-mcp-server, and PBRemote, with required checks, normalized
  status, deterministic scores, and an ecosystem summary. Opening the row shows
  the bounded per-product report; no source contents, commands, or network probes
  are involved.
- **Runtime resource budgets** — GUI/web/CLI preview safety profiles now carry a
  shared `pblang.resource_budget.v1` contract for wall time, worker count,
  output, frames, and frame time. `app_run_resource_report(...)` rejects runaway
  usage and supplies adaptive actions such as reducing workers, lowering frame
  rate, or rendering only dirty regions. Management exposes the active policy;
  opening it prints the current file's guarded preview limits.
- **Child-app resilience** — The same preview safety profile carries a
  `pblang.resilience.policy.v1` and initial lifecycle state. Native GUI/web child
  apps receive at most two launch attempts with capped backoff and the same wall
  deadline as their resource budget; headless previews remain one-shot. This is
  deterministic launch policy, while blocking child I/O remains protected by the
  process/watchdog timeout at the execution boundary.
- **AAP portfolio action planning** — `project_survey.portfolio_action_plan(...)`
  extends the readiness board into ranked implementation tasks. Each task carries
  a project/category, impact/effort/risk score, device route, suggested protocols
  or algorithms, and required safety/verification gates. This is meant for
  choosing the next focused implementation slice, especially PBIDE GPU-present
  rendering, pbAI curated training, pbOS capability layers, and pb-mcp tool
  classification, without scanning private file contents. `stdlib:project_inventory.sapp`
  and `tools/pbportfolio.sapp` expose metadata-only coverage while pruning
  secret/cache/build locations. Scan-derived tasks are currently fail-closed:
  they cannot feed this board until the inventory proves allocation bounds,
  mount confinement and tri-state entry identity. Broad `/media` or home scans
  therefore remain blocked rather than being treated as trustworthy idea input.
- **AAP category health matrix** — Management also exposes
  `ide_features.project_category_health_board(...)`, backed by
  `project_survey.portfolio_category_health(...)`. It shows every focus category
  for pblang, pbAI, pbOS, PBIDE, pb-mcp-server, and PBRemote with present/missing status,
  high-risk missing markers, priority, device route, protocols, gates, and the
  next safe step. This makes broad improvement requests actionable without
  pretending that all projects are fully audited or complete.
- **Project gap/security audit board** — Management can also consume
  `ide_features.project_gap_board(...)`, backed by `stdlib:project_audit.sapp`,
  to summarize caller-provided TODO/not-implemented/placeholder/security/
  reliability/performance markers. This is bounded text analysis only: it does
  not walk the filesystem, and it gives Watchers/Management a shared contract
  for prioritizing fixes before touching the renderer. The board now includes
  the shared `quality_gate` result and a bounded backlog, so Management can show
  whether the current project data is clean, needs review, or blocked. Audit
  suppressions are explicit and reasoned, so fixture/example noise can be
  lowered without hiding real security or reliability blockers.
- **Bounded project text audit** — `stdlib:project_text_audit.sapp` and
  `tools/pbaudit.sapp` provide the explicit filesystem bridge for the audit
  board. They inventory only caller-approved roots, skip secret/cache/build
  paths, read only small text-like files, cap file count and byte size, and print
  redacted summaries instead of raw source lines. Use this when PBIDE/Watchers
  need a real project scan while preserving the safer metadata-only default.
- **AAP one-command status** — Management exposes an on-demand `AAP project
  status` row backed by `ide_features.project_aap_status_board(...)` and
  `stdlib:aap_status.sapp`. The row is deliberately lazy so normal Management
  redraws stay fast; pressing Enter runs a capped source/docs status pass for
  pblang/PBIDE, pbAI, pbOS, pb-mcp-server, and PBRemote, then prints a
  redacted pass / needs-review / blocked summary plus a ranked `next focus`
  queue and safe drill-down detail for the next project/category to improve.
- **Project gap delta board** — `ide_features.project_gap_delta_board(...)`
  compares before/after bounded audit records and reports fixed/new/unchanged
  counts through the shared `progress_gate`. This gives Watchers/Management a
  regression signal for PBIDE work: cleanups pass, new blockers fail by default.
- **Micro GUI foundation** — `stdlib/micro_gui.sapp` is the new small-app-first GUI substrate: it builds compact render plans and hit targets without opening a window, supports label/button/field/checkbox/progress widgets, tracks dirty/signature state, optimizes command lists, estimates render cost, and attaches honest device-route metadata such as `low-memory-rects` or `cpu-raster-gpu-present`. It has a runnable `examples/micro_gui_counter` project. This is the intended path for future PBIDE panel simplification: move heavy hand-drawn panels toward cached, optimized, device-aware plans before adding more visual complexity.
- **Help/Manual** — shortcut overlay and documentation-oriented panel.

## Screenshot-driven fixes tracked

The screenshots showed three main native IDE problems:

1. **Greek/web text mojibake or unreadable entity text.** Fixed in `stdlib/browser.sapp` by improving entity decoding, title decoding, whitespace collapse, and reader parsing. PBIDE now prefers native anti-aliased TrueType/OpenType text through `pblang-graphics`/`fontdue`, with `stdlib/text_layout.sapp` providing the pblang-owned shaping layer for clusters, simple bidirectional runs, code ligatures, and emoji variation cleanup. The pblang graphics layer now also chooses a cleaner UI font candidate stack by default instead of going straight to the odd-looking bitmap/monospace fallback. The compact bitmap font remains a safe fallback. Full HarfBuzz-class shaping and color-font emoji painting are still future renderer parity work, but normal code/editor text is no longer limited to blocky 5×7 glyph rendering.
2. **Browser panel looked unlike the web reader.** Improved by separating reader text, links, and parsed forms at the engine level. Forms UI is now the next UI task rather than a missing parser task.

## Honest gaps

- **Full Unicode/rendering polish** is not done, but the old pixel-only text limitation is fixed. PBIDE now uses native anti-aliased TrueType/OpenType text by default with a bitmap fallback, plus a pblang-owned shaping layer for combining clusters, simple bidi ordering, code ligatures, and emoji variation cleanup. Remaining renderer gaps are HarfBuzz-class shaping, robust font fallback stacks, CJK coverage, complex bidirectional layout, and color-font emoji painting.
- **Arbitrary emoji identifiers/operators** are not enabled. Unicode is supported for strings, comments, editor text, and tooling helpers; the parser grammar still keeps identifiers/operators conservative for stability.
- **Browser layout/interactivity** is pblang-native for high-signal flow content in Live/Reader/Source/Inspect modes: headings, paragraphs, images, links, and forms now have tested layout-box geometry and hit targets. Full CSS cascade, flex/grid, canvas/SVG painting, DOM mutation, and JavaScript execution are still not implemented natively. The optional Host tab delegates exact DOM/CSS/JS layout to a host Chromium/Chrome/Brave/Edge/Firefox-compatible renderer when installed and allowed. The `JS/DOM` security profile is that explicit host-render opt-in, not a complete pblang-native JavaScript engine or DOM implementation yet.
- **Office/PDF/media editing** is a structured preview/editor/backend contract today. TXT/Markdown/HTML/CSV can use the text/table buffer path, while DOC/DOCX/DOC/ODT/RTF/PPT/PPTX/XLS/XLSX/PDF/image/audio/video assets need native decoder/export/player implementations before deep in-place editing is real. PBIDE now exposes mode/tool/export/player readiness and blocked-action requirements so those backends can be attached without changing the user workflow.
- **Engine integration** is a scene/component contract today. pblang can describe cameras/lights/materials/physics/prefabs/render targets, but it does not embed Unreal, Unity, Godot, OpenGL, or Vulkan runtimes directly yet.
- **Interactive verification** still needs human testing across display backends, keyboard layouts, DPI settings, and focus behavior.
- **Performance** is improved for large buffers, but can still improve further with a host `gfx_draw_text` primitive or row-run batching.

## Migration plan

1. Keep the web IDE as the reference workflow.
2. Bring native panels to web-parity feature by feature.
3. Add regression fixtures for every screenshot-level bug.
4. Attach real native decoder/export/player implementations behind the existing document/media backend contracts.
5. Retire `index.html` only when the native IDE reaches real workflow parity.
