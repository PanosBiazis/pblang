# pblang-native IDE — browser-free, for total security

> **Goal.** Make the IDE completely written in pblang — no HTML, CSS, or JS — while matching the web IDE's workflow as closely as possible.

The native IDE is the self-hosted Studio direction of the project: editor, terminal, designer, AI helper, browser, and run/check history are pblang code running on pblang's own runtime. The Code panel runs and checks through `stdlib/compiler/selfhost_frontend.sapp`, and the tested self-host path can bundle imports and emit `.pbck`; the Rust VM remains the native execution kernel and fallback for now. The web IDE remains useful as a bootstrap/reference UI, but the native IDE is the long-term security-first target.

---

## Why — the security argument

The browser IDE (`editors/ide/index.html`) is convenient, but a web IDE brings browser attack surface:

| Web-stack layer | Attack surface it adds |
|---|---|
| HTML parser | malformed-markup / injection bugs |
| DOM + `innerHTML` | XSS and content-injection bugs |
| CSS engine | layout/parser exploits and data exfiltration tricks |
| JS engine | JIT bugs, prototype pollution, dependency surface |
| `fetch`/iframes | SSRF, content-injection, sandbox escapes |

A pblang-native IDE removes those layers. The whole IDE is a native window, a pixel buffer, input events, and pblang code under pblang's capability model. There is no DOM, no JS runtime, and no HTML renderer to exploit.

## Architecture

```text
        ┌─────────────── editors/ide/pbide.sapp ───────────────┐
        │  native window + event loop                           │
        │  code editor | terminal | designer | AI | browser      │
        │  self-hosted run/check + toolchain status               │
        │  history snapshots + restore                           │
        ├───────────────────────────────────────────────────────┤
        │  stdlib/editor_model.sapp   buffer + cursor + edits   │
        │  stdlib/bitmap_font.sapp    5×7 glyphs → pixels       │
        │  stdlib/browser.sapp        fetch + reader parser     │
        │  stdlib/browser_render.sapp optional host screenshot  │
        │  stdlib/gui.sapp            designer widget model     │
        │  stdlib/design_engine.sapp  responsive 2D/3D layout   │
        │  stdlib/ui_observer.sapp    structured UI snapshots   │
        │  stdlib/pbai.sapp           local pblang assistant    │
        │  stdlib/graphics.sapp       window / rect / present   │
        └───────────────────────────────────────────────────────┘
```

## Current native panels

- **Code** — editor, syntax highlighting, selection, undo/redo, find, save, run, check, output pane, watcher, and a visible toolchain block showing the self-hosted pblang frontend plus native VM boundary.
- **Terminal** — runs real PC commands through `proc_spawn_wait` when launched with `--allow-exec` or `--allow-all`.
- **Design** — native visual designer with label/button/textbox/checkbox/radio/select/slider/panel palette, app target mode (`gui` / `web` / `both`), 2D chart, runnable 3D cube/ball widgets, scanner placeholders, N-dimensional item placeholders, custom/web component placeholders, and game-engine-style placeholders for camera, light, material, terrain, particles, physics body, prefab, and OpenGL/Vulkan-style render backend targets. It supports responsive layout cycling, bounded drag/move/edit behavior, snapped placement/drag/keyboard nudging/resizing, selection cycling, duplication, layer ordering, and parse-checked `->CODE` generation into the editor.
- **AI** — local pbAI assistant with quick actions: explain, bugs, improve, quality, comment. The assistant exposes structured analysis metadata, prompt-history recall, draft restoration, and raw scan metrics.
- **Browser** — pblang-native safe Live/Reader/Source/Inspect view using `stdlib/browser.sapp` to enforce an HTTP/HTTPS URL policy, block unsafe schemes/private hosts/credential URLs/CRLF input/non-web service ports plus known ad/tracker/malicious URL patterns by default, fetch pages, decode entities, strip scripts/styles, extract page blocks/images/links/forms, clean noisy reader lines, deduplicate repeated navigation text, list discovered forms, show numbered HTML source, and show F12-style details. `Host` is an explicit opt-in external snapshot fallback through `stdlib/browser_render.sapp`.
- **Files** — persistent pblang-native project browser backed by `fs_listdir`. It lists folders before files, supports type-to-filter, flat/tree/recent mode with `Tab`, bounded recursive tree browsing, multi-root bookmarks/cycling, directory navigation, refresh, mouse selection, and opening files into the editor.
- **History** — web-IDE-style run/check snapshot list. Every native Run/Check records status, output summary, and source snapshot; clicking a row restores that code into the editor.
- **Help/Manual** — shortcut overlay and documentation-oriented panel.

## Screenshot-driven fixes tracked

The screenshots showed three main native IDE problems:

1. **Greek/web text mojibake or unreadable entity text.** Fixed in `stdlib/browser.sapp` by improving entity decoding, title decoding, whitespace collapse, and reader parsing. The native bitmap font now has compact glyphs for common Greek/math/code symbols, while broader Unicode shaping still belongs to a future text renderer.
2. **Browser panel looked unlike the web reader.** Improved by separating reader text, links, and parsed forms at the engine level. Forms UI is now the next UI task rather than a missing parser task.
3. **Native IDE parity was unclear.** This document now separates implemented, partial, and pending web-parity items.
4. **AI panel felt shallow.** Improved in `stdlib/pbai.sapp` with structured `analyze()` metadata, quality scoring, sensitive-capability risk summaries, more pblang-specific knowledge (typeclasses, logic, reactive streams, security), and a native IDE `QUALITY` quick action.
5. **Code side pane had placeholders.** The diagnostics/history boxes now show actionable check guidance and the latest action instead of "pending" text.
6. **Toolbar parity gaps.** Native Format now uses `stdlib/compiler/formatter.sapp` behind a parse/lint guard; Auto-fix applies deterministic pblang fixes including inline `print(x);` forms; Examples cycles built-in starter programs; Open uses a native Quick Open file picker.
7. **Panel tabs were unreachable in the new toolbar.** Fixed by splitting the toolbar into left-side actions and right-pinned panel tabs (`Code`, `Term`, `AI`, `Designer`, `Browser`, `Files`, `Out`, `Prob`, `Hist`), plus keyboard fallbacks (`F2`/`F3`/`F4`/`F7`/`F9`/`F10`), `Ctrl+1..9` panel switching, and `Ctrl+Tab` / `Ctrl+Shift+Tab` panel cycling. `F8` is reserved for diagnostics parity with the web IDE.
8. **Some embedded examples did not run through F5.** Replaced fragile snippets with self-hosted-runner-compatible examples and added `tests/semantics/pbide_examples_test.sapp`.
9. **Newer screenshots showed `+N` overlap near Open and weak style choice.** Removed the hidden-action counter, shortened core toolbar actions, and added a visible `Style` cycle (`Web` → `Smooth` → `Contrast` → `Pixel`). `PBIDE_SCALE=1` remains the launch-time escape hatch for smaller text.
10. **Open looked broken before the buffer file existed or when another panel was active.** `Open` now switches to Code and starts a native Quick Open picker (`Enter` opens files or enters directories, `Esc` cancels, typing filters). Save defaults to a repo/session-local `.pbide_buffer.sapp` and falls back there if the previous path fails.
11. **Fractional line numbers appeared after mouse clicks.** Mouse-to-buffer math and `editor_model.set_cursor` now floor fractional coordinates before clamping.
12. **Designer needed a real layout foundation.** Added `stdlib/design_engine.sapp`: backend-neutral 2D/3D item model, snapping, anchors, responsive grid/stack layout, hit-testing, and isometric 3D projection. The native Designer now has `CUBE3D`/`BALL3D` palette items and a `LAYOUT` cycle for free/responsive/grid/stack positioning.
13. **Designer layout crashed on normal GUI widgets.** Fixed `design_engine.sapp` to treat `min_w`/`min_h` as optional, so `gui.sapp` widgets and design-engine 3D items can be reflowed together.
14. **Native IDE lacked the web IDE's History workflow.** Added a `Hist` panel (`F9`) backed by pure `stdlib/ide_features.sapp` history helpers. Run/Check now save bounded snapshots, status, and output summaries; clicking a history row restores its source into the editor.
15. **Native diagnostics were text-only.** F6 now stores normalized diagnostics, the code side pane lists real diagnostic rows, clicking a row jumps to the inferred location, and F8/Shift+F8 navigate next/previous diagnostics like the web IDE.
16. **Native output pane was fixed-width.** Added web-IDE-style splitter dragging in the Code panel. The output pane now resizes during the session and is clamped so the editor and output pane both remain usable.
17. **Native examples only rotated one-by-one.** The `Ex` toolbar action now opens a web-IDE-style searchable picker. Type to filter by title/code, use list navigation to select, Enter to load, Esc to close, or click a row.
18. **Native browser needed safer protocols.** `stdlib/browser.sapp` now rejects non-HTTP(S) schemes (`file:`, `javascript:`, `data:`, etc.) and blocks loopback/LAN/private hosts by default before fetch or form submit. Local/private browsing must be an explicit opt-in by the caller.
19. **Native browser needed a page-like view without embedding a browser.** Added a `Live` mode backed by pblang page blocks: title/headings/paragraphs/images/forms are extracted and rendered natively as styled live cards. This improves visual similarity to the web IDE while keeping the no-DOM/no-JS security boundary.
20. **Large buffers made editing feel laggy.** Code rendering now draws syntax tokens in one visible-pass instead of scanning all tokens once per row, and syntax coloring pauses on very large buffers so editing remains responsive.
21. **Pasted mathematical notation was not pblang source.** Added `stdlib/math_symbols.sapp` and wired native IDE `Fix` to normalize common symbols and shortcuts (`π`, `Π`/`∏`, `τ`, `φ`, `√`, `×`, `÷`, `≤`, `≥`, `≠`, `∧`, `∨`, `¬`) into valid pblang-friendly code. `π` means the pi constant; `Π`/`∏` mean product / repeated multiplication and normalize to `product(...)`.
22. **2026-06-21 screenshot: Browser Page view showed raw Google links and broken image/navigation text.** Page mode now filters corrupt/noisy blocks, stops dumping raw URL links into the page body, keeps Links mode as the URL list, and uses a wider content column.
23. **2026-06-21 screenshot: native UI still felt too pixel-sized.** Default `PBIDE_SCALE` is now `1` with a 1280×760 minimum window, giving a cleaner web-like density. Set `PBIDE_SCALE=2` or higher for larger text.
24. **Typing numbers/symbols varied by backend key names.** `stdlib/keymap.sapp` now accepts direct digits (`"1"`), `Digit1`, `Key1`, `Num1`, and `Numpad1`-style names, plus numpad arithmetic keys.
25. **Exact page rendering needed an optional comparison path.** Added `stdlib/browser_render.sapp` and a native IDE `Host` mode. It uses an installed Chromium/Chrome/Brave/Edge/Firefox-compatible browser in headless screenshot mode, after the same pblang URL policy passes. Live/Reader/Source/Inspect stay the safe no-DOM/no-JS pblang-native defaults; Host needs `--allow-exec`.
26. **Browser protocols needed stronger malicious-action blocking.** URL policy now rejects credential-bearing URLs, control/space/CRLF input, and common non-web service ports such as SSH, SMTP, Redis, Postgres, MySQL, Elasticsearch, and MongoDB before fetch/render/submit.
27. **IDE typing needed symbol composition.** The editor can expand math shortcuts like `\pi`, `\Pi`/`\prod`, `\sqrt`, `\le`, `\ge`, `\ne`, `\sum`, and `\int` by pressing Space or Tab after the shortcut. `stdlib/keymap.sapp` also recognizes more punctuation aliases and direct Unicode character keys from capable backends/IMEs.
28. **Control shortcuts needed backend-independent modifier names.** `stdlib/keymap.sapp` now recognizes common Shift/Ctrl/Alt/Meta aliases from SDL, minifb, browser-style, and platform-style key names, and the graphics backends attach direct `shift`/`ctrl`/`alt`/`meta` booleans to key events. Shortcuts such as `Ctrl+A`, `Ctrl+O`, `Ctrl+S`, and `Ctrl+P` no longer fall through as typed letters when the backend reports `LeftCtrl`, `ControlLeft`, or only a modified letter event.
29. **Code text needed broad character support.** pblang strings now support braced Unicode scalar escapes such as `\u{1F600}` for emoji, the pblang-written tokenizer decodes the same escapes, and the native IDE accepts direct emoji/symbol text input. The native bitmap font includes compact glyphs for common math/Greek symbols plus a few emoji smoke-test glyphs, and unknown symbols render as visible missing-glyph cells instead of collapsing to `?`.
30. **IDE needed real project/build state like normal IDEs.** Added `stdlib/ide_features.sapp` watcher/build-profile helpers and wired the native IDE toolbar/status/side pane to them. Debug mode runs `Check` before `Run` and blocks on diagnostics; Release mode runs directly for speed. Watcher tracks buffer hash, revision, dirty/clean state, line count, symbol count, diagnostic count, deltas, and a bounded event log. F11 toggles Debug/Release; F12 toggles Watcher.
31. **Native IDE needed a command palette.** Added a `Ctrl+P` command palette backed by `stdlib/ide_features.sapp` command catalog/filter helpers. It exposes Run, Check, Save, Open, Format, Fix, Examples, Debug/Release, Watcher, panel switches, and Help from one searchable modal with Up/Down/Enter/Esc and mouse selection.
32. **Native IDE needed symbol navigation like the web IDE.** Added the `Out` panel backed by `stdlib/ide_features.sapp` outline/filter helpers. It lists top-level functions, variables, constants, and exports; typing filters symbols, Up/Down changes selection, Enter or click jumps to the source line, and Esc returns to Code.
33. **Native IDE toolbar actions needed safer behavior.** Format now refuses to replace the buffer when formatted output fails parser validation or increases diagnostics. Fix handles inline `print(...)` statements inside one-line functions and common `fs read`/`fs write` typos. Render now falls back to Firefox when Chromium/Chrome/Brave/Edge are not installed, which fixes the common `www.google.com` Render failure on Firefox-only systems.
34. **Browser needed pblang-owned rendering and F12-like details.** Added pblang-native `Live`, `Source`, and `Inspect` modes. `Live` draws page structure as native cards instead of a screenshot, `Source` shows numbered HTML source, `Inspect` shows URL/status/policy/counts/elements/links/images/forms like a compact DevTools panel, and the visible Back button now uses session history.
35. **Designer 3D code failed under IDE Run and needed app-type targeting.** Generated Designer apps now default to a headless `preview()` that runs through the IDE self-host runner, expose `run_gui()` for opening the real GUI window, emit responsive `gui.fit_form(...)`, generate first-class `gui.cube3d(...)` / `gui.sphere3d(...)`, and carry an `app_target()` value selected by the Designer `APP` mode (`gui`, `web`, or `both`).
36. **Designer items needed IDE-grade keyboard control.** Selected Designer items now move with arrows, resize with `Ctrl+arrows`, use a larger step with `Shift`, clamp inside the canvas, expose size in the inspector strip, and keep manual sizes stable while text-like widgets are edited.
37. **Designer placement needed cleaner alignment.** New placement, mouse dragging, keyboard movement, responsive layout application, and `Ctrl+arrow` resizing now snap to the native Designer grid while still clamping items inside the usable canvas.
38. **Designer selection and layers needed real builder controls.** `Tab` / `Shift+Tab` cycles selected items, `Insert` duplicates the selected item with a deep-copied metadata/component tree, and `Ctrl+[` / `Ctrl+]` moves the selected item backward/forward in the drawing order (`Shift` sends it to back/front).
39. **Open needed a real native file picker.** Added a pblang-native Quick Open modal backed by `fs_listdir` and `stdlib:ide_features.sapp` filtering. It lists directories before files, supports type-to-filter, Up/Down/PageUp/PageDown/Home/End plus `Ctrl+N`/`Ctrl+P` selection, result counts, selected-position details, Enter to open or enter a directory, mouse row selection, and typed-path fallback when no row matches.
40. **Native IDE needed persistent project browsing, not only Quick Open.** Added a `Files` panel backed by the same pblang-native directory model. It keeps a current directory, supports filtering, Enter/click to open files or enter directories, Backspace to go up, Ctrl+R refresh, and uses the normal editor open path.
41. **Files needed an IDE-style tree view without becoming slow on large repos.** The `Files` panel now toggles flat/tree mode with `Tab`. Tree mode is bounded by depth and entry count, preserves indented display labels through the shared picker, and skips generated-heavy folders such as `target`, `.git`, `node_modules`, `.cache`, and `.mint-mcp`.
42. **Watcher needed useful live state instead of one static summary.** Watcher updates now compute line/symbol/diagnostic deltas, keep a newest-first event log, expose `watcher_lines(...)` for UI rendering, and ignore unchanged draw refreshes so idle repaints do not hide the last meaningful event.
43. **Diagnostics needed freshness tracking.** The watcher now records whether diagnostics are `unchecked`, `fresh`, or `stale`. A successful Check marks the current buffer hash fresh; later edits mark diagnostics stale until the next Check, and the native side pane highlights stale watcher rows.
44. **Watcher state needed a direct next action.** Added `watcher_action(...)` and a command-palette `watch_action` command. The Code side pane now shows an action row such as `diagnostics stale - press F6 Check`; running the watcher action from the command palette routes stale/unchecked diagnostics through the normal Check path, fresh diagnostics through F8 navigation, and clean dirty buffers through Save.
45. **Watcher actions needed mouse parity.** Clicking the watcher action row in the Code side pane now runs the same watcher action as the command palette, so stale diagnostics can be refreshed without leaving the editor surface.
46. **Watcher state was too verbose in the status bar.** Added `watcher_badge(...)` for compact status text (`watch ok`, `watch stale`, `watch err N`, etc.). The bottom status bar now uses the compact badge, and the Watch toolbar button shows short state labels such as `Stale`, `ErrN`, `Dirty`, `Unchk`, or `Watch` with warning/error colors where useful.
47. **Diagnostics needed command-palette reachability.** Added `Problems`, `Next diagnostic`, and `Previous diagnostic` commands. `Problems` refreshes stale/unchecked diagnostics through Check, jumps to the first fresh diagnostic when issues exist, or reports no problems for a clean fresh buffer.
48. **Problems needed a dedicated native panel.** Added the `Prob` panel. It shows the watcher action row followed by current diagnostics, supports Up/Down/PageUp/PageDown, Enter/click to run the action or jump to the selected diagnostic, F6 refresh, and Esc back to Code.
49. **Designer generated code could be fragile.** Native Designer now emits a web-IDE-style `build()`/`main()` wrapper using `gui.sapp`, validates generated source with `frontend_parse_safe` before replacing the editor buffer, generates runnable placeholders for 3D items, clamps dragged items inside the canvas, refreshes label hit boxes while editing, and supports radio/select/slider widgets.
50. **Designer needed extensible item/component contracts.** `stdlib/visual_engine.sapp` now models custom components, foreign-language metadata components, HTML/CSS/JS web components, scanner-imported components, path/group 2D nodes, sphere/surface 3D nodes, and N-dimensional item nodes. The native Designer exposes safe placeholders for chart/custom/web/scanner/ND items; generated `gui.sapp` code remains runnable and does not execute foreign JS or external code.
51. **Native browser needed ad/tracker/malicious blocking.** `stdlib/browser.sapp` now has deterministic `classify_url_threat(...)` / `threat_policy(...)` checks and applies them from `url_policy(...)`, blocking common tracker/ad/malicious URL patterns before fetch, form submit, or Render.
52. **Some Code panel controls were easy to miss or overlap.** The toolbar hit-test now matches the visible button band more tightly, the Code side pane no longer overlaps Diagnostics and History rows, and the native editor now supports web-style `Ctrl+Enter` Run, `Ctrl+Shift+Enter` Check, `Ctrl+D` Designer, `Ctrl+B` Browser, and `Ctrl+I` AI fallbacks.

## Honest gaps

- **Full Unicode rendering** is not done. The current native font has compact glyphs for common math/Greek symbols and falls back visibly for unknown characters; full shaping, combining marks, bidi text, and CJK/font fallback need a real text renderer.
- **Arbitrary emoji identifiers/operators** are not enabled. Unicode is supported for strings, comments, editor text, and tooling helpers; the parser grammar still keeps identifiers/operators conservative for stability.
- **Browser layout** is pblang-native in Live/Reader/Source/Inspect modes. The optional Host tab delegates exact DOM/CSS/JS layout to a host Chromium/Chrome/Brave/Edge/Firefox-compatible renderer when installed and allowed.
- **Engine integration** is a scene/component contract today. pblang can describe cameras/lights/materials/physics/prefabs/render targets, but it does not embed Unreal, Unity, Godot, OpenGL, or Vulkan runtimes directly yet.
- **Interactive verification** still needs human testing across display backends, keyboard layouts, DPI settings, and focus behavior.
- **Performance** is improved for large buffers, but can still improve further with a host `gfx_draw_text` primitive or row-run batching.

## Migration plan

1. Keep the web IDE as the reference workflow.
2. Bring native panels to web-parity feature by feature.
3. Add regression fixtures for every screenshot-level bug.
4. Replace remaining pending actions: richer Browser form widgets such as per-control inline editing UI, and continued project-browser polish such as persisted roots.
5. Retire `index.html` only when the native IDE reaches real workflow parity.
